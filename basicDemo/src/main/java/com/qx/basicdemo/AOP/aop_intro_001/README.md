# 第 001 节: AOP 是什么

## 这节只记一句话

AOP 是一种在**不修改原业务代码**的前提下, 给方法增加额外功能的思想。

## 先看一个直觉例子

如果我们有一个 `createOrder()` 方法:

- 业务本身只想做下单
- 但系统还想额外做日志记录
- 还可能要做权限校验
- 还可能要做异常记录

如果这些代码都写进 `createOrder()` 里, 业务方法会越来越乱。

AOP 的想法就是:

把“日志、权限、异常处理”这些**横切关注点**抽出去, 在方法执行的前后统一织入。

## 你现在项目里的对应关系

- `OrderService`: 业务类
- `LogAspect`: 切面类
- `AopDemoRunner`: 演示入口

## 这一节先只理解

AOP 不是替代 OOP。

它是对 OOP 的补充, 专门解决“很多方法都要重复做一遍的公共逻辑”。
