## 教学 Skill

**目标**：针对「语言的某类方法/特性」进行系统化教学。

### 0. 前置调查(轻量、必要)
- 询问用户：
  - 对该特性是否有过了解(完全陌生 / 听说过 / 用过基础 / 熟练)
  - 希望的学习深度(快速了解 / 能看懂代码 / 能熟练使用 / 能应对面试或项目)
  - 可选：熟悉的其它语言(便于类比教学)

> *注意：若用户完全陌生，则降低使用率阈值和难度起点。*

---

### 1. 知识点总览与教学大纲

- 定义该特性是什么、解决什么核心问题
- 明确本次教学的范围与边界(包含与不包含哪些东西)
- 给出大纲结构

---

### 2. 知识点筛选(“先导预览”)

按用户使用场景和场景下使用频率分层展示：

- **必选知识点(使用率 ≥50%)**
- **可选知识点(使用率 10%~50%)**

> *展示时介绍名称 + 用途，不展开代码。*

---

### 3. 目录树结构(教学顺序)

- 每个节点格式：`知识点名称`
- 排序规则(权重公式建议)：
  - **教学优先级 = 前置程度 * 重要程度 * 使用率 + 难易程度(1~5，越简单越低值)**

示例(Java 异常)：
```
├── 1. 异常基本概念
│   ├── 1.1 什么是异常
│   ├── 1.2 异常 vs 普通错误
│   ├── 1.3 异常体系的顶层结构
│   ├── 1.4 异常发生时的默认行为
│   └── ...
│
├── 2. try-catch-finally
│   ├── 2.1 try 块：标记可能出错的代码区域
│   ├── 2.2 catch 块：捕获并处理指定异常类型
│   ├── 2.3 多个 catch 块的顺序规则
│   ├── 2.4 finally 块：无论是否异常都会执行
│   ├── 2.5 try-finally 组合
│   └── ...
│
├── 3. checked vs unchecked
│   └── ...
│
├── 4. throw / throws
│   └── ...
│
├── 5. 自定义异常
│   └── ...
│
└── 6. try-with-resources
    └── ...
```

---

### 4. 教学内容

**每个子知识点包含至少四部分**：

1. **概念与动机**
   - 为什么需要它 / 解决什么问题
2. **简单使用示例**
   - 最典型、最干净的形式
3. **教学例题**(1-3 个)
   - 贴近真实使用场景
   - 包含输入/输出或行为说明
   - 例题难度不超过该小节内容
4. **教学例题**(10+ 个)
   - 所有的例题所需知识点覆盖整个小节的内容
   - 需要一定的难度
   - 内容综合

> *规范：例题不依赖后续小节的内容。*

---

### 5. 完善：层间钩子与难度控制(“审阅与重构”)

在完成第一版内容后，逐节检查并做以下动作：

- **钩子**
  在每一节的合适的教学内容里，安排一些钩子，如“当遇到xx时，会出现什么问题。后续的xx就是用来解决xx问题的”

- **难度降级**
  如果某节连续出现 ≥2 个陌生概念，拆出一节前置微教学

- **内容深化**
  在后期小节中，尝试在保证本节教学内容目标不变的情况下，多'强迫'用户使用前面学过的内容

---

### 6. 润色规范(面向学习者)

- 统一术语
- 所有代码：可运行、语义完整
- 避免“显而易见的废话”
- 复杂示例前加一句：“如果你不理解 A，可以先记住模式，第 X 节后会回看”

---

### 7. 最终收尾与检验

- 小节练习汇总(2~4 道综合题)
  - 必须用到 ≥3 个小节的知识
  - 每个题目明确标注「所需章节」
- 给出参考答案 + 常见错误点
- 可选延伸阅读(哪些内容本次不讲但很有用)

---

## 额外规范

| 规范 | 说明 |
|------|------|
| 规范5 | 每个子知识点必须有「示例 + 例题」，不能只有概念 |
| 规范6 | 前置知识若不在本次范围内，用 `<aside>` 形式给出最小解释，不展开教学 |
| 规范7 | 示例与例题必须可以独立理解，不依赖上下文中的隐藏假设 |
| 规范8 | 练习题必须覆盖「必选知识点」的全部，并按照知识点比重安排练习题内容 |
